A screening tool
for where the labs aren't

Type 2 diabetes is the rare disease that is both easy to detect and routinely missed. The test is cheap and the treatment works, yet across Africa most people living with diabetes have never been diagnosed. This project asks a narrow question: can eight measurements a primary health centre can already obtain be turned into a reliable prompt to go get tested?

Architecture

Three layers, one job each

The codebase is organised so that each layer has exactly one responsibility and depends only on the layer beneath it. Clinical facts live in one place, the model lives in another, and the interface knows nothing about either.

{# ------------------------------------------------- DESIGN DECISIONS -- #}
Design decisions

Choices worth defending

{% for item in [ {'q': 'Why is the language model not allowed to recall clinical facts?', 'a': 'Because it recalls them imperfectly and cannot tell you when it has. Every threshold the explanation cites is injected into the prompt from who_idf_thresholds.json, and the system prompt forbids introducing any figure that was not supplied. The model is used for what it is reliably good at - rewriting structured facts into readable prose - and nothing else.'}, {'q': 'Why does the app work with no API key at all?', 'a': 'A screening result that cannot be explained is worse than useless. A deterministic writer composes the same three paragraphs directly from the knowledge base, and it runs whenever no provider is configured, the network fails, or the model declines the request. The interface always discloses which one produced the text you are reading.'}, {'q': 'Why replace the supplied dataset?', 'a': 'The CSV this project started with had already been cleaned by replacing missing values with the median of each outcome class. That writes the answer into the feature: insulin 102.5 meant a negative outcome every time and 169.5 meant positive, across 49% of all rows. A model trained on it scored 0.95 ROC-AUC by reading the label. The pipeline now downloads the original data and refuses to train on any copy that fails an integrity and leakage check.'}, {'q': 'Why tune the threshold instead of using 0.5?', 'a': 'Because the two errors are not equally costly. A false positive sends someone for a blood test they did not need; a false negative tells an at-risk person they are fine. The threshold was lowered until 80% of true cases are caught, and the loss in specificity was accepted deliberately rather than inherited from a default.'}, {'q': 'Why is nothing stored?', 'a': 'Health measurements are sensitive and this tool has no need for them after scoring. There is no database, no analytics, and no logging of submitted values. Responses are sent with no-store so nothing lands in a shared cache.'}, {'q': 'Why hand-written CSS?', 'a': 'The design system is small, specific, and opinionated: flat surfaces, one border colour, two type families, pill controls. A framework would ship far more than is needed and would have to be fought to produce this. Every rule in it is used.'} ] %}
